## 首屏拆解（实验室，中位数样本）

- **关键路径就是 HTML 文档本身**：ready ≈ TTFB + HTML 传输（fast4g 下 115KB ≈ 230ms）
- 字节构成：首页/列表 script ≈135KB；文章页 script ≈201KB（评论、点赞、分享等客户端组件），link(CSS) 20KB
- 文章页有 55.5ms 主线程长任务（水合）；首页/列表基本没有（0ms）
- **Link prefetch 风暴**（load 后发生，不阻塞 ready，但消耗真实服务器资源）：首页/列表会对每个链接的文章页发起 `?_rsc=` 预取——每条预取都是一次完整的动态 SSR + 数据库查询；文章页预取 about/contact/projects/blog。访客每看一页，服务器要多渲染 4–5 页
- 确定性计数（棘轮已锁定）：首页 27 请求/188.5KB，列表 25/183.6KB，文章 26/280.2KB；主线程长任务总量见上

## 局限（如实记录）

- 实验室绝对值 ≠ 生产绝对值（数据库内容量、CPU、网络不同）；本冲刺的结论以「同机同时段 A/B 配对测」的相对降幅为准，上线后以线上复测为最终结论
- 本地库无评论/点赞/合集数据，涉及这些区域的优化需上线后单独验证
- CrUX 缺失，真实用户分布未知

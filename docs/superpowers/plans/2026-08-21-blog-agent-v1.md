# Single-Blog Floating Agent V1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a secure floating Agent to each published public Markdown Blog so visitors can ask a single question grounded only in the current article and jump to cited headings.

**Architecture:** The route resolves one public Blog by URL slug, parses its latest Markdown on demand, and selects evidence only inside that article. A server-only OpenAI-compatible client performs at most one grounded completion; PostgreSQL stores only quotas, generation events, and answer cache entries. The Blog page renders a floating robot and responsive panel only when both server-side feature flags are enabled.

**Tech Stack:** Next.js 16 App Router, React 19, Payload CMS 3, PostgreSQL 15, `pg`, TypeScript, Vitest, Testing Library, `react-markdown`, `remark-gfm`, lucide-react.

**Spec:** `docs/superpowers/specs/2026-08-21-blog-agent-v1-design.md`

## Global Constraints

- Blog is the only data and security boundary; never list, retrieve, cite, or load a second Blog.
- V1 accepts only the current Blog's `contentMarkdown`; RichText-only, draft, private, and missing Blogs are unavailable.
- No standalone `/ask`, embedding, pgvector, external URL retrieval, file upload, tool write, conversation history, local Codex connection, or publishing Skill change.
- Request question is 1–500 trimmed characters; raw body is at most 8 KiB.
- Evidence is at most 5 sections and 14,000 characters; completion output is at most 600 tokens; provider timeout defaults to 15 seconds.
- The model receives only published public Markdown excerpts and cannot choose links; citation URLs are generated by the server.
- The answer renderer permits safe Markdown text, lists, emphasis, inline code, and fenced code only; raw HTML, images, iframe, and model-created links are disabled.
- Both `BLOG_AGENT_ENABLED` and `BLOG_AGENT_GENERATION_ENABLED` default to `false`; no API key is exposed through a `NEXT_PUBLIC_` variable.
- Do not modify `/Users/jinkun.wang/.codex/skills/publish-site-article` in this plan.
- Write new explanatory comments in Chinese only where they clarify a non-obvious security invariant or tradeoff.

```ts
export type ArticleSection = {
  id: string;
  heading: string;
  headingPath: string[];
  anchor: string;
  ordinal: number;
  content: string;
};

export type ArticleEvidence = {
  title: string;
  excerpt: string;
  outline: Array<{ id: string; headingPath: string[]; anchor: string }>;
  sections: ArticleSection[];
  totalCharacters: number;
};

export function buildArticleEvidence(input: {
  title: string;
  excerpt: string;
  markdown: string;
  question: string;
  maxCharacters?: number;
  maxSections?: number;
}): ArticleEvidence;
```

Implementation rules:

- scan lines while tracking fenced code blocks;
- create a synthetic `top` section only for content before the first real heading;
- normalize heading anchors, preserve Chinese and ASCII words, and suffix duplicates with `-2`, `-3`;
- if all section content fits the character budget, preserve every section in source order;
- otherwise score only sections from this parsed document using normalized ASCII tokens plus Chinese character bigrams, choose at most 5, add adjacent sections only when the budget permits, and restore document order before returning;
- truncate only at paragraph boundaries when one selected section exceeds the remaining budget.
